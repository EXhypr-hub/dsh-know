# 安全说明

这份文档记录本插件的安全审计结果：**修了什么、确认安全的是什么、已知限制有哪些**。
初版审计时间 2026-11-17（对应版本 0.6.0）；2026-11-18 对 0.6.8 做了补充审计，
新增 Z4–Z7 四项修复，并复核了原有结论。

---

## 一、已修复的漏洞

### Z4 · SSRF 绕过（DNS 解析与重定向，高危，已修）

**问题**：v0.6.7 及以前只检查 URL 主机名的字符串写法。两条绕过路径：

1. **DNS rebinding**：公网域名把 A/AAAA 记录指向 `127.0.0.1`，主机名字符串校验通过，
   实际连接却是本机；
2. **重定向**：`fetch(..., { redirect: 'follow' })` 由运行时直接跟随 302，
   公网 URL 重定向到 `http://127.0.0.1` 或 `http://169.254.169.254` 时不再经过任何校验。

**修复**（`lib/fetch-policy.js` + `index.js`）：

1. 新增 `resolvePublicHost()`：请求前先做 DNS 解析，所有解析结果都必须通过内网判断；
2. 抓取改为手动跟随重定向（最多 5 跳），**每一跳**都重新执行协议 / 内网 / DNS / 白名单校验。

**回归测试**：`安全：SSRF 内网拦截` 覆盖 20 种地址变形；新增用例断言
「重定向到内网地址必须被拒绝」。

---

### Z5 · OCR Key 明文落库（中危，已修）

**问题**：嵌入 API Key 走 DSH 凭据库（不可用时落 0600 权限的 `secrets.json`），
OCR Key 却直接写进 SQLite 的 `settings` 表明文，与「API Key 只存凭据库」的承诺不一致。

**修复**：OCR Key 改走与嵌入 Key 相同的凭据通道（键 `dsh-knowbase/ocr-api`，
文件兜底为 `ocr-secrets.json`，权限 0600）；旧版 `settings.ocrKey` 读取时自动迁移并删除。

**回归测试**：`安全：OCR Key 不落 settings`。

---

### Z6 · 跨库共享文件被单方删除（数据损坏，已修）

**问题**：文件副本按内容哈希全局共享，同一文件导入两个库只存一份物理文件；
但删除任一库中的文档或整个库时会无条件删掉该文件，其他库的文档随后
「重新解析」直接 ENOENT。

**修复**：删除前用 `countDocumentsByHash()` 做引用计数，只有没有任何文档再引用时才删物理文件。

**回归测试**：`安全：跨库共享文件删除`。

---

### Z7 · 模型下载成功即崩溃（功能不可用，已修）

**问题**：`lib/models.js` 的 `integrity` 变量声明在镜像循环内部，成功分支在循环外引用，
首个文件下载成功即抛 `ReferenceError`。原有自测只做源码字符串检查，未真正执行下载。

**修复**：变量声明提升到文件级；自测改为本地 HTTP 服务端到端执行。

**回归测试**：`安全：模型下载执行路径`。

---

### Z1 · ZIP 炸弹（高危，已修）

**问题**：docx / xlsx / pptx 本质是 ZIP。旧实现直接 `inflateRawSync(raw)` 解压，没有输出上限。
一个几十 KB 的构造文件可以解压出几 GB，把 DSH 进程撑爆（OOM），连带整个应用卡死。

**修复**：`lib/extract.js` 的解压加上两道闸——

| 闸 | 上限 | 覆盖场景 |
|---|---|---|
| 单条目 | 64MB | 单个 `document.xml` 被撑爆 |
| 累计 | 256MB | xlsx 含上千个条目，合起来仍然爆炸 |

超限时抛出可读的中文错误，而不是让进程被杀掉：

> 压缩包里的「word/document.xml」解压后体积异常（超过 64MB），已中止。这可能是压缩炸弹，也可能是文档本身损坏。

同时校验中央目录声明的 `compressedSize` 不得为负、不得越出 buffer 边界。

**回归测试**：`scripts/selftest.mjs` 的「安全：ZIP 炸弹防护」构造一个 100KB 的真实压缩炸弹，断言被拦下；同时断言正常文档仍能读。

---

### Z2 · SSRF 内网探测（高危，已修）

**问题**：联网抓取有内网拦截，但只识别标准写法的 IPv4 和裸 `::1`。
同一台机器的回环地址有多种等价写法，攻击者（或诱导模型抓取的网页）可以用变形绕过：

| 写法 | 实际指向 | 修复前 |
|---|---|---|
| `2130706433` | 127.0.0.1 | ❌ 放行 |
| `0x7f000001` | 127.0.0.1 | ❌ 放行 |
| `0177.0.0.1` | 127.0.0.1（八进制） | ❌ 放行 |
| `127.1` | 127.0.0.1（省略段） | ❌ 放行 |
| `::ffff:127.0.0.1` | 127.0.0.1（IPv6 映射） | ❌ 放行 |
| `::ffff:7f00:1` | 127.0.0.1（十六进制映射） | ❌ 放行 |

**修复**：`lib/fetch-policy.js` 的 `isPrivateHost()` 重写——

1. 新增 `parseIpv4()`，按 `inet_aton` 规则解析十进制/十六进制/八进制/省略段各种写法
2. 先剥掉 IPv6 映射前缀 `::ffff:`，再判断
3. 补充组播与保留段（`224+`、`ff::`）
4. 最后一道兜底：解析不出结构、但看起来全是数字与点和 `x` 的主机名，一律拒绝

**回归测试**：20 种内网变形必须全拦，8 个公网地址必须全放行（防止过度拦截误伤正常抓取）。

---

### Z3 · HTML 正则退化（中危，已修）

**问题**：网页正文抽取用多个正则剥离 `<script>` 等标签，
超大的恶意 HTML 可能让正则退化，拖慢甚至卡住进程。

**修复**：`extractHtml()` 限制输入 8MB，超出部分截断后再处理。

## 二、确认安全的项

| # | 面 | 结论 | 依据 |
|---|---|---|---|
| S1 | SQL 注入 | 安全 | 全部 17 处 `prepare` 使用 `?` 参数化；3 处模板插值分别是表名常量、FTS5 短语（内部转义 `"`）、`VACUUM INTO` 的路径（转义 `'`） |
| S2 | 命令注入 | 安全 | 唯一的 `spawn` 用于 `npm install`，参数是固定数组 `['install','--no-audit','--no-fund']`，无用户输入 |
| S3 | 路径穿越 | 安全 | 上传文件与原文件副本一律用 `sha256` 命名（`filePath(sha256, ext)`），用户提供的文件名只用于显示标题，不参与路径拼接 |
| S5 | 凭据泄露 | 安全 | 嵌入与 OCR 的 API Key 都只存在凭据库（不可用时落 0600 权限的本地 secret 文件），从不写入日志、不拼进 `error.message`、不进入导出文件；settings 表不再保存任何 Key |
| S6 | XSS | 安全 | 客户端无 `innerHTML` / `dangerouslySetInnerHTML`；检索高亮是构造 React 节点而非拼 HTML 字符串 |
| S8 | 资源耗尽 | 已限 | 单文件 50MB（抓取可配置到 100MB 上限）、上传 base64 解码前预检查、批量导入/上传 200 个文件、OCR 单次 20 页（写入时夹紧）、单页渲染 2048px |
| S9 | 原型污染 | 安全 + 加固 | 配置合并全部用对象展开（走 `CreateDataProperty`，不触发 setter），实测 `__proto__` 不会污染原型；另加 `sanitizeConfig()` 在 6 个配置入口显式过滤 `__proto__`/`constructor`/`prototype` |

## 三、默认安全姿态

| 行为 | 默认 |
|---|---|
| 联网抓取 | **关闭**。关着完全不联网 |
| 本地嵌入 | 不主动下载模型，用户点了才下 |
| OCR | **关闭**。扫描件只入库不抽取 |
| 数据外发 | 仅当用户主动配置 API 嵌入/重排/OCR 时，对应文本或图片才会发往该服务 |
| 内网地址 | 无论抓取开关是否打开，始终拒绝（含 DNS 解析结果与每一跳重定向） |
| robots.txt | 遵守，被禁止的路径不抓 |
| 同站点请求 | 间隔 ≥ 2 秒 |

## 四、已知限制（不是漏洞，但你需要知道）

1. **命中的片段会进入对话上下文**，因此也会随这次对话发给当前对话模型。这是「让模型带着资料回答」的必要代价。
2. **抓来的资料能否商用/再分发由你判断**。插件只负责记录来源 URL 与站点声明的许可，不做法律判断。
3. **本地 OCR 的准确率**受图片质量影响，复杂表格与手写体效果有限。
4. **不防御恶意网站的内容本身**。抓取只做文本抽取，不执行页面脚本，但抓回来的文本可能含误导性内容——模型引用时仍需你自己判断可信度。
