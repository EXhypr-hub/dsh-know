## 它做什么

把你自己电脑上的文档变成一个可以语义检索的知识库，让模型在回答前先查你的资料，
并把书名和页码一起给出来。**所有数据留在本机。**

## 三个使用场景

**资料太多找不到**：几百份 PDF、表格散在硬盘里。拖进来后，用大白话提问就能定位到具体片段。

**答案要有出处**：模型不再靠记忆作答，而是先检索你的库，引用格式为「（《文档名》第 12 页）」。

**建专题库缺来源**：内置 14 条权威站点清单（NSTL、国家统计局、arXiv、OpenStax、求是网等），
每条带许可提示，模型可按清单取用。

## 怎么用

1. 左侧栏点「知识库」图标
2. 新建一个库，把文件拖进虚线框
3. 在「检索设置」里接入嵌入模型——两种方式：
   - **API**：选服务商（内置 13 家 / 47 个模型），贴 Key，点「测试连接」
   - **本地模型**：下载模型后完全离线，不需要 Key
4. 点「建立向量索引」
5. 到「检索测试」里搜一句自然语言，看能不能命中

之后在对话里问相关问题，模型会自动调用 `kb_search` 并引用出处。

## 支持哪些文件

PDF、Word（.docx）、PowerPoint（.pptx）、Excel（.xlsx）、Markdown、TXT、HTML。

旧版 `.doc` / `.ppt` / `.xls` 需要先用 Office 另存为新格式。扫描版 PDF 没有文字层，
会被标记为「需 OCR」——OCR 功能尚未提供。

## 隐私边界

| 操作 | 数据出不出本机 |
|---|---|
| 拖入文件、切块、建索引（本地模型） | 不出 |
| 检索你的库 | 不出 |
| 使用 API 嵌入或重排 | 文本片段发往该 API |
| 联网抓取来源 | 只向目标站点发出请求，不发库内容 |

命中的片段会进入对话上下文，因此也会随这次对话发给当前对话模型——
这是「让模型带着资料回答」的必要代价。

## 联网抓取

默认**关闭**，关着完全不联网。开启后：

- 可访问任意公开 http/https 站点（按你的要求，白名单是可选而非强制）
- 但会拒绝内网地址、遵守 robots.txt、同站点间隔 2 秒、单文件 ≤100MB
- 每份抓来的文档记录来源 URL 与站点声明的许可
- 遇到登录、付费、验证码会失败并说明原因，不做绕过

## 已知限制

- **Excel / PPT 结构复杂**：合并单元格、图表说明里的文字会丢失，只保证正文可读
- **扫描件**：没有文字层的 PDF 需要 OCR，该功能尚未提供
- **版权**：抓来的资料能否商用、能否再分发由你自行判断，插件只负责记录来源与许可
- **大库性能**：暴力向量检索在 10 万块以内表现良好，再大需要换索引方案

## 数据位置

默认在 `%USERPROFILE%\.dsh\knowbase\`，包含 `kb.sqlite`（索引）、`files/`（原文件副本）、
`models/`（本地模型）。备份时整个目录复制走即可。
